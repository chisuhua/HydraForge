## ADR 概述

ADR-0086 定义**信用分配契约 (Credit Assignment Contract)** — 评估层 (IEvaluator/RewardSignal, ADR-0083 已 ship) 回答"这次执行好不好", 归因层 (AttributionRecord, 本 ADR 新增) 回答"**表现变化应归因于哪个主体、哪个变异、哪个环境变化**"。二者零重叠。

**缺口定位** (self-evolution §一.1.3 + §四 4.2): 已 ship 基础设施 (IEvaluator / 行为回归门 / MutationGovernor / Session 4-Scope / TrajectoryIR / EventLog) 各自回答自进化闭环的单点问题, 但**没有任何组件回答"这次提升/下降归因于谁"**。例如 GEPALoop 提交新 prompt 后 eval score +0.08 — 这 +0.08 归因于新 prompt, 还是任务恰好变简单, 还是 evaluator 噪声? 当前无法回答。这正是 self-evolution §五 禁止行为 ("在信用分配缺失时, 不得把相对胜负、单次成功或环境变简单认定为自身能力提升") 试图防止的误判场景。

**本 ADR 是 Axis6 Phase 1 的唯一前置 blocker** (`openspec/changes/2026-08-31-mcts-axis6-cognitive-domain/` tasks §7.1), 也是 self-evolution §六 S4 协同进化 promotion criteria 的首项。
