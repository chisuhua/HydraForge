## 推荐执行顺序

### Wave 2-A (并行 — Foundation, parallel_group=0)

两个 change **互相无序**，均无上游依赖（除已 ship 的 ADR foundation）：

1. **`cli-args-cxxopts`** (P2, ~3d, ~25-30 tasks)
   - 主要交付：vendored cxxopts → `external/cxxopts/` + `examples/pdk_chat_demo/cli_args.{h,cpp}` 声明式 flag table + main.cpp:76-83 替换
   - 文件 overlap：`examples/pdk_chat_demo/main.cpp` (与 session-tree-tui + chat-streaming-slash-tui 共享，但 Wave 2-A 先 ship 清理 baseline)
   - 推荐先 ship（清理 main.cpp audit baseline，给 Wave 2-B 提供干净的 flag 声明基础）

2. **`provider-dynamic-discovery`** (P2, ~3-4d, ~30 tasks)
   - 主要交付：`LLMProviderFactory::register_dynamic()` + thread-safety (shared_mutex) + `provider/refresh` + `provider/register_dynamic` + `provider/switch` 3 个工具
   - 文件 overlap：`src/common/llm/llm_provider_factory.{h,cpp}` (核心修改) + `pdk/provider_agent/` 3 个新工具文件
   - 推荐并行 ship（与 cli-args-cxxopts 无 main.cpp 冲突，可并行开发 + 各自 worktree）

**Wave 2-A 内顺序选项**：

**方案 A (推荐 — 无依赖并发)**：两个 worktree 并行 ship，commit 不交叉
- 优点：最大化吞吐量，团队容量允许并发 PR
- 风险：两者改动 main.cpp 之外，无交叉点，零冲突

**方案 B (串行)**：先 cli-args-cxxopts → 后 provider-dynamic-discovery
- 优点：低风险
- 风险：浪费 1-1.5 周时间（无依赖却串行）

**推荐** 方案 A。

### Wave 2-B (并行 — Wave 2-A ship 后启动, parallel_group=1)

两个 change **互相无序**，均依赖 Wave 2-A 完成：

1. **`session-tree-tui`** (P2, ~2d, ~20 tasks)
   - 主要交付：2 个 flag `--fork <node_id>` + `--name <session_name>` 在 cli_args 表中声明 + main.cpp 启动序列 (parse → load_session → fork_node → enter_chat_loop)
   - 文件 overlap：`examples/pdk_chat_demo/cli_args.{h,cpp}` (Wave 2-A ship 后扩展 flag 表) + `examples/pdk_chat_demo/main.cpp` (启动序列新增)
   - 推荐先 ship（任务体量较小，作为 Wave 2-B 收尾前置）

2. **`chat-streaming-slash-tui`** (P1, ~5-6d, ~50-60 tasks) — 唯一 P1
   - 主要交付：`EventHandler` chunk-level subscriber (订阅 `llm.response` + `loop.*`) + `--system-prompt` + `--append-system-prompt` flag + render/session 解耦 + 预算告警保留
   - 文件 overlap：`src/modules/executor/event_handler.{h,cpp}` (核心修改) + `src/common/contract/in_memory_bus.{h,cpp}` (订阅扩展) + `examples/pdk_chat_demo/cli_args.{h,cpp}` (2 flag 扩展) + `examples/pdk_chat_demo/main.cpp` (system-prompt 应用)
   - 推荐并行 ship（与 session-tree-tui 在 cli_args.{h,cpp} 各加 2 行声明，可自动合并）

**Wave 2-B 内顺序选项**：

**方案 A (推荐 — 大小优先)**：先 `session-tree-tui` → 后 `chat-streaming-slash-tui`
- 优点：先 ship 较小项目给 main.cpp 增加 baseline，为 chat-streaming 提供 audit 干净 base
- 风险：后者需要 rebase 处理 cli_args.{h,cpp} 合并

**方案 B (并行)**：两个 worktree 并行开发，merge 时 rebase + 解决 cli_args.{h,cpp} 冲突
- 优点：压缩总时长 1.5-2 周
- 风险：并发 PR 增加 review 负担，但 cli_args.{h,cpp} 冲突可自动合并（不同 flag 行）

**推荐** 方案 A — 与 Wave 1 推荐方案一致 (大小优先)，团队 review bandwidth 仍是约束。

### Wave 3 (deferred — Wave 2-B ship 后启动)

- **`chat-async-io-steering`** (P2, ~5d) — design-handoff v2 标记为 "Wave 3 after W2 ship"
- 依赖 chat-streaming-slash-tui ship 后具备完整事件链路（loop.* + 流式）
- 本 plan cycle **不纳入**，design-handoff 标记为下一 design cycle 重审

- Wave 2-A 内 `cli-args-cxxopts` ↔ `provider-dynamic-discovery`: **零冲突** (完全独立模块)
- Wave 2-B 内 `session-tree-tui` ↔ `chat-streaming-slash-tui`: **主冲突** = `examples/pdk_chat_demo/cli_args.{h,cpp}` + `examples/pdk_chat_demo/main.cpp`

- 跨 Wave `cli-args-cxxopts` ↔ `session-tree-tui`/`chat-streaming-slash-tui`: **依赖关系而非冲突** (Wave 2-A 先 ship，Wave 2-B 在其上层扩展)
