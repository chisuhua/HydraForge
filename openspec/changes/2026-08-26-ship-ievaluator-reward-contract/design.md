# Design: ship-ievaluator-reward-contract

## Overview

Ship IEvaluator/RewardSignal contract as pure virtual interface + value types, with optional evaluator injection into CognitiveWorker/DomainWorkerPool via setter (non-breaking). V1 implements TaskSuccessEvaluator only; V2 evaluators (BehavioralEquivalence/Composite) are explicitly out of scope.

## Design Decisions

### D1 — IEvaluator as Pure Virtual Interface

```cpp
// include/agenticdsl/contract/ievaluator.h
class IEvaluator {
public:
    virtual ~IEvaluator() = default;
    virtual RewardSignal evaluate(const ExecutionTrace& trace) const = 0;
    virtual int compare(const ExecutionTrace& a, const ExecutionTrace& b) const = 0;
};
```

- **Thread-safe requirement**: Implementations MUST be const and thread-safe (multiple workers may call concurrently).
- **Side-effect-free**: `evaluate()` and `compare()` MUST NOT mutate external state or emit events.
- **V1 implementation**: `TaskSuccessEvaluator` (maps `ToolResult.ok` to quality).
- **V2 implementations**: Out of scope (BehavioralEquivalenceEvaluator, CompositeEvaluator).

### D2 — RewardSignal Three-Valued + Scalar

```cpp
// include/agenticdsl/types/reward_signal.h
struct RewardSignal {
    enum class Quality { Excellent, Acceptable, Poor };
    Quality quality;
    double scalar;        // in [-1.0, 1.0], throws std::out_of_range if violated
    double confidence;    // in [0.0, 1.0], for RLHF/DPO gradient weighting

    static RewardSignal excellent(double confidence = 1.0);
    static RewardSignal acceptable(double confidence = 1.0);
    static RewardSignal poor(double confidence = 1.0);
};
```

- **scalar range**: [-1.0, 1.0], validated by factory methods; out-of-range throws `std::out_of_range`.
- **quality → scalar default mapping**: Excellent=1.0, Acceptable=0.0, Poor=-1.0 (customizable by evaluator).
- **confidence semantics**: Used for RLHF/DPO gradient weighting; 0.0=unreliable, 1.0=confident.

### D3 — ExecutionTrace vs TraceRecord Division

- **TraceRecord** (existing, `include/agenticdsl/types/trace_record.h`): Low-level event log (tool calls, timestamps, spans).
- **ExecutionTrace** (new, `include/agenticdsl/types/execution_trace.h`): High-level task-completion summary:
  ```cpp
  struct ExecutionTrace {
      ToolResult final_result;        // terminal ok/error/data
      std::string trace_id;           // links to TraceRecord
      std::vector<std::string> trajectory_refs;  // opaque refs to intermediate steps
  };
  ```
- **Construction**: Workers construct `ExecutionTrace` from terminal `ToolResult` + `trace_id` after task completion.
- **trajectory_refs**: V1 empty; V2 may populate with intermediate step identifiers.

### D4 — Optional Setter Injection (Non-Breaking)

```cpp
// include/agenticdsl/cognitive/cognitive_worker.h
class CognitiveWorker {
public:
    // Existing constructor UNCHANGED:
    CognitiveWorker(std::unique_ptr<DSLEngine>, std::shared_ptr<IInteractionBus>);
    
    // New optional setter:
    void set_evaluator(std::shared_ptr<IEvaluator> evaluator);
    
    // Internal default: TaskSuccessEvaluator if no external evaluator set
};
```

- **DomainWorkerPool**: Same pattern (setter + internal default).
- **Default behavior**: Workers use internal `TaskSuccessEvaluator` if no external evaluator injected.
- **Thread-safety**: Setter assumes single-threaded initialization (called before workers start); no mutex required for V1.

### D5 — evaluation_id Generation and Propagation

- **generation**: Opaque unique identifier generated by evaluator implementation (e.g., UUID, timestamp-counter).
- **event schema**: `evaluation.result` event payload:
  ```json
  {
    "evaluation_id": "<opaque-unique-id>",
    "trace_id": "<existing-trace-record-id>",
    "reward": {
      "quality": "Excellent|Acceptable|Poor",
      "scalar": 0.5,
      "confidence": 1.0
    },
    "schema_version": "v1"
  }
  ```
- **downstream consumption**: Mutation governance (ADR-0084) receives `evaluation_id` in `MutationContext.evaluation_refs` array for audit trail.
- **V1 scope**: `evaluation_id` generated but not persisted; V2 may add evaluation history storage.

### D6 — Event Emission Timing

- **CognitiveWorker**: Emit `evaluation.result` AFTER existing `cognitive.task.completed` event (sequential, same thread).
- **DomainWorkerPool**: Emit `evaluation.result` AFTER existing `domain.task.completed` event (sequential, same thread).
- **EventBuilder integration**: Reuse existing `EventBuilder` for `evaluation.result` topic (registered in ADR-0068 Appendix A v1.2).

### D7 — TaskSuccessEvaluator V1 Mapping

```cpp
// src/common/evaluator/task_success_evaluator.cpp
RewardSignal TaskSuccessEvaluator::evaluate(const ExecutionTrace& trace) const {
    if (trace.final_result.ok) {
        return RewardSignal::excellent(1.0);  // ok=true → Excellent(1.0, conf=1.0)
    } else {
        return RewardSignal::poor(1.0);       // ok=false → Poor(-1.0, conf=1.0)
    }
}
```

- **V1 simplification**: No intermediate-step analysis; purely terminal `ToolResult.ok`.
- **compare() V1**: Returns 0 (equality) always; meaningful comparison requires V2 BehavioralEquivalenceEvaluator.

## Integration Points

1. **CognitiveWorker**:
   - Constructor: UNCHANGED.
   - New method: `set_evaluator(shared_ptr<IEvaluator>)`.
   - Internal default: `TaskSuccessEvaluator` instance.
   - Event emission: After `cognitive.task.completed`, construct `ExecutionTrace` + call `evaluator->evaluate()` + emit `evaluation.result`.

2. **DomainWorkerPool**:
   - Constructors: UNCHANGED.
   - New method: `set_evaluator(shared_ptr<IEvaluator>)`.
   - Internal default: `TaskSuccessEvaluator` instance.
   - Event emission: After `domain.task.completed`, construct `ExecutionTrace` + call `evaluator->evaluate()` + emit `evaluation.result`.

3. **EventBuilder**:
   - No API changes; directly emit `evaluation.result` with full payload.
   - Topic registered in ADR-0068 Appendix A v1.2 (Owner: CognitiveWorker/DomainWorkerPool).

4. **ADR-0084 Mutation Governance**:
   - Consumes `evaluation_id` via `MutationContext.evaluation_refs` array.
   - No direct coupling; evaluator contract is producer-only.

## Out of Scope (V1)

- BehavioralEquivalenceEvaluator (trajectory fingerprinting + comparison).
- CompositeEvaluator (multi-evaluator aggregation).
- Evaluation history persistence.
- Trajectory intermediate-step capture (ExecutionTrace.trajectory_refs remains empty).
- Cross-worker evaluator coordination.

## Verification Gates

- `ctest -N` baseline + new `test_evaluator` cases ≥4 (not fixed total).
- `evaluation.result` event schema verified via EventBuilder assertions.
- `scalar` range validation test (out-of-range throws `std::out_of_range`).
- `confidence` field present in all factory methods.
- ADR-0068 Appendix A contains `evaluation.result` row.
- ADR-0083 status remains 🔍 Proposed until code ships.
